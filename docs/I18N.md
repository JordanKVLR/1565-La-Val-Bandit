# Translating Armatura 1565

The game ships in English only, but none of its text is fixed in code. This page says where each
kind of text lives and how to add a language. The design is in
[ADR 0012](adr/0012-ui-string-table.md).

## Where the text is

| Text                                                                                                  | Where                                          | How it is translated                                                         |
| ----------------------------------------------------------------------------------------------------- | ---------------------------------------------- | ---------------------------------------------------------------------------- |
| **UI**: menus, buttons, settings, HUD, battle log, help, Armoury, notices, screen-reader labels       | `apps/game/src/i18n/en.ts`                     | A table per language (below).                                                |
| **Story**: dialogue, narration, choices, chapter cards                                                | `packages/content/story/*.ink`                 | Not wired yet. Ink supports string tables or one script per language.        |
| **Content data**: names and descriptions of characters, weapons, skills, codex entries, achievements… | `packages/content/data/*.json`                 | Not wired yet. Planned as per-language tables keyed by id, next to the JSON. |
| **Starting techniques** (Slash, Thrust, Fire…)                                                        | `packages/core/src/attacks.ts`                 | Treat as content data, keyed by attack id.                                   |
| **Store and OS names**: page title, PWA manifest, Electron window                                     | `index.html`, `vite.config.ts`, `apps/desktop` | The game's name; translate per store listing if needed.                      |

Thrown errors, test ids, CSS classes and console logs are for developers and stay in English.

## The UI table

`en.ts` is the source. Each entry is a stable key and its English text:

```ts
'menu.saveToSlot': 'Save to slot {n}',
'roster.pointsToSpend': { one: '{n} point to spend', other: '{n} points to spend' },
'settings.iosHint': 'On iPhone, tap Share, then <b>Add to Home Screen</b> to play full screen.',
```

- `{name}` is a placeholder. Keep every placeholder; move it wherever your grammar needs it.
- An object is a **plural**: give the forms your language uses (`zero`, `one`, `two`, `few`,
  `many`, `other`; see the
  [CLDR plural rules](https://www.unicode.org/cldr/charts/latest/supplemental/language_plural_rules.html)).
  `other` is always required. The number is `{n}`.
- `<b>…</b>`, `<strong>…</strong>` and `<em>…</em>` mark emphasis. Keep the tags around the
  matching words.
- Prompts that name the input come in three sentences, one per device:
  `prompt.continue.pointer` ("Tap to continue"), `.keyboard` ("Press Enter to continue") and
  `.gamepad` ("Press {button} to continue"). Translate each as a whole sentence.
- `common.sep` (" · "), `common.listSep` (", ") and `objective.or` (" or ") join lists. Change
  them if your language punctuates lists differently.
- Comments in `en.ts` explain entries whose meaning is not obvious.

In code, every string a player reads comes from `t()`:

```tsx
import { t, tParts, tRich } from '../i18n';

t('menu.saveToSlot', { n: 2 }); // "Save to slot 2"
tParts('menu.difficulty', { name: <strong>{name}</strong> }); // text with an element inside
tRich('settings.iosHint'); // emphasis tags become <b> elements
```

Keys and placeholders are type-checked. `pnpm lint` rejects words written straight into JSX text
or into `aria-label`, `title`, `placeholder`, `alt` or `label` under `apps/game/src`. The
tests reject unused keys.

## Adding a language

1. Copy `apps/game/src/i18n/en.ts` to, for example, `mt.ts`, rename the export to `mt` and
   type it as a translation:

   ```ts
   import type { MessageTable } from './format';
   export const mt: MessageTable = {
     'common.back': 'Lura',
     // …
   };
   ```

   Every key is optional: in a production build a missing one falls back to English. In a
   development build (`pnpm dev`) it shows as `⟦key⟧`, so gaps are easy to spot.

2. Register it in `LOCALES` in `apps/game/src/i18n/index.ts`:

   ```ts
   export const LOCALES = { en, mt };
   ```

   At start-up the game picks the first language in the player's browser or system preferences
   that it ships (`pickLocale`), else English.

3. Run `pnpm test`. `i18n/en.test.ts` checks every shipped table against English: no unknown
   keys, the same placeholders, plural forms where English has them and plain text where it
   does not, no empty text.

4. Play it with `pnpm dev` and look for `⟦key⟧`, clipped text and buttons that grew too wide.
   Buttons must stay at least 44 px and fit a small landscape phone (the e2e `phone-landscape`
   project) and the TV layout (ADR 0010).

There is no in-game language menu yet. It would set `setLocale()` from a setting and remount the
screens. Story and content data need their own tables before a language is complete.
